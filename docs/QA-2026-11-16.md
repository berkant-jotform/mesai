# Local reliability checkpoint — 16 November 2026

Not published. The local source and all bookmark variants contain these fixes.

## User-impacting fixes

- Invalid backup files are validated before applying any field. A wrong-shaped file cannot partially replace settings or delete plans; the tool explains that nothing changed.
- Invalid saved-state types no longer prevent startup. The original browser value remains untouched and a save warning is shown. An explicitly selected valid backup can repair the corrupted slot.
- An unfinished time entry survives another tab's settings update. Its date context is checked, so it cannot silently carry over into a different week.
- A failed-save warning stays visible across storage updates until a save actually succeeds. The unsaved edit remains available for retry or backup.
- A temporarily blank portal table cannot erase attendance already read for that month. Reading resumes when valid rows return.
- Updating to a different build with the same version label replaces the old widget. Clicking the identical bookmark still keeps one instance.
- Closing the widget stops queued work; a backup file that finishes reading after close cannot overwrite the active session.
- A timed-out automatic month read attempts to restore the user's original period instead of abandoning the portal on the temporary month.

## Reproduce the maintained checks

```sh
npm ci
npx playwright install chromium
npm run qa
```

`npm test` runs pure calculations, scenarios, persistence, undo, Turkish parsing,
milestone logic, and a 748-case independent reliability matrix. `e2e` runs the
built bookmark against an asynchronous simulated portal, including recovery tests.
`test:installer` checks every downloadable theme, selection races, and failed
bookmark-download recovery. `test:distribution` verifies exact installer/runtime
agreement, embedded resources, distribution identity and the URL size budget.

The browser-test dependency is pinned in the package files. Build before browser
tests. The primary installer always contains the full package; per-theme links
must match their manifest bytes exactly.

## Evidence and limits

Machine-readable results and round-by-round screenshots are in the workspace's
`qa-reports/2026-11-16/extensive-qa/`. Early rounds intentionally contain failures;
use `summary.json` and the report to find the verified final runs. Final recovery checks are in `final-recovery/`; the broader Chrome regression is in `release-gate/chrome/`.

These are disposable local browser profiles and synthetic portal data. Installed
personal browser profiles, real attendance and colleagues' saved data were not
used. WebKit's recovery checks use real keyboard activation because its headless
pointer driver on this Mac delivers incorrect coordinates. They do not establish
branded Safari pointer compatibility.

Real ARGE acceptance remains necessary, particularly the affected colleague's
same-day reset report. Before a public release, verify actual bookmark save/reopen,
multiple portal tabs, and a return visit with that colleague. Browser storage may
still be cleared by the browser, private-session exit or organizational policy;
the tool cannot promise persistence when storage itself is unavailable. Old tabs
running an older public implementation must be refreshed during the eventual
update. No GitHub push was performed for this checkpoint.
